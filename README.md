# 集训之夜 · 监控室

> 一个 OIer 做的生存小游戏。你是机房里最后一个还在改代码的人，
> 用监控撑过 23 个小时（0:00 → 23:00）。

**在线试玩**：https://cld123cld.github.io/oi-night-game/

---

## 玩法

你是机房里最后一个还在改代码的人。教练不会让你熬夜 —— 但你还有题没过。

用监控盯住各个角落，撑过 **23 个小时**（0:00 → 23:00）就算赢。

### 三个麻烦

| 角色 | 行为 | 怎么应对 |
|---|---|---|
| **主教练** | 走 办公室 → 走廊 → 大门 | 他到门口时**关上大门**能挡住，但门会被撞掉耐久。耐久归零就破门 |
| **副教练** | 走 后窗 → 你的身后 | **关门对他没用**。他溜到你身后时，你必须在 **7 秒内**切到刷题模式并**保持**，让他以为你在学习。**盯着摄像头吓不退他** |
| **同学** | 待在集训教室 | 你不看教室，他的**捣乱条**就涨；满了就 **JC 你**：**大门一定被撞开，就算主教练正堵在门口也一样**。盯着教室能把捣乱条压下去 |
| **打断** | 来自同学 | 你刷题时若同学已闹到一定程度，他会**把你从刷题模式拽出来**，专注和心流清零。这是对"一直刷题"的直接反制 |

修门必须**先开门** —— 修的时候如果主教练在门口，直接没了。

### 你要干什么：刷题

**光活着没用 —— 你得把题刷完。** 这正是这个游戏和一般生存游戏最大的区别。

整晚有一条 **题目进度**，只有**刷题模式**下才会涨：

| 难度 | 达标线 | 刷题速度 | 约需多少比例的时间刷题 |
|---|---|---|---|
| 简单 | 60% | 0.18 %/秒 | ~47% | 1 × 6s |
| 普通 | 70% | 0.19 %/秒 | ~59% |
| 困难 | 80% | 0.24 %/秒 | ~60% |
| 地狱 | 85% | 0.29 %/秒 | ~59% |
| 史诗 | 92% | 0.34 %/秒 | ~62% |

**心流机制**：连续刷题 **30 秒以上**进入心流，效率 **×1.3**；一中断就重新累积。
所以 *长刷效率高但危险，短刷安全但慢* —— 第二层取舍。

**副教练因此变成了"带收益的威胁"**：他逼你去刷题 7 秒，那 7 秒进度照涨。
收益和风险绑在一起。

于是形成核心取舍：

| 选择 | 收益 | 代价 |
|---|---|---|
| 疯狂刷题 | 进度飞快 | 看不见监控 → 同学 JC、主教练推门 |
| 一直盯监控 | 防守稳 | 进度不动 → 熬到天亮题一道没过 |

### JC：门一定会被撞开

**同学 JC 你时，大门一定被打开 —— 不管主教练在不在门口。**

这正是 JC 最吓人的时刻：同学把你卖了，而教练正好站在门外。

早先版本为了防"无解死"（副教练逼你刷题 7 秒期间没法关门，同学这时开门 + 主教练进门 = 必死），
改成"主教练堵门口时 JC 不开门"。但这把同学的威胁感整个抹掉了。

现在的做法是**给反应时间而不是取消事件**：

```
JC 开门 → 若主教练在门口，给 3 秒宽限
       → 宽限期内他会站在敞开的门口犹豫，你可以把门关回去
       → 3 秒后还没关 → 他进门，游戏结束
```

既保留了戏剧性，又不会让你死得莫名其妙。把这 3 秒救回来可以解锁成就 **「极限救门」(S)**。

### 同学会打断你刷题

你在刷题模式时，如果同学捣乱值已经累积到一定程度，他会**时不时把你拽出来**：

- 强制切回监控模式
- **专注秒数与心流立刻清零**（心流要连续 30 秒才触发，所以打断代价很大）
- 有 15 秒冷却，不会连续骚扰
- **简单档不会打断**，越难的档打断越频繁

这是对"一直刷题"策略的直接惩罚——刷得越久、他闹得越凶，你被拽出来得越勤。

### 三种结局

| 结局 | 条件 | 含义 |
|---|---|---|
| 🟢 **撑过去了** | 活到 23:00 **且**进度达标 | 真正的通关 |
| 🟡 **熬了个寂寞** | 活到 23:00，但进度不够 | 人是活的，题一道没过 |
| 🔴 **被抓到了** | 中途被抓 | — |

### 操作

- 右侧 **1~6 号按钮** 或键盘 `1`-`6`：切换摄像头
- `空格`：切换 监控 / 刷题
- `Q`：开关大门　`E`：维修大门

### 难度

简单 / 普通 / 困难 / 地狱 / 史诗。

## ⚡ 断电模式

深夜机房会**跳闸**。断电期间：

- 监控**全黑**，什么都看不见
- **大门状态未知**（状态栏显示「？？？」）
- **同学捣乱条隐藏**，你看不到他什么时候 JC
- 副教练靠近也**不会报警**
- 摄像头按钮上的警报灯全部熄灭

**但刷题进度照常累积。**

所以断电时闭眼刷题，是**用安全换进度的一次赌**。

| 难度 | 断电次数 × 时长 |
|---|---|
| 简单 | 1 × 6s |
| 普通 | 2 × 7s |
| 困难 | 3 × 8s |
| 地狱 | 4 × 9s |
| 史诗 | 4 × 8s |

### 为什么断电时"大门被冻结"

这是整个机制的关键：**你看不见，就没法反应**。

断电期间大门保持断电瞬间那个状态，你无法更改。所以真正的技巧点是
**提前关门** —— 在断电来临前把门关好，然后安心闭眼刷题。

（第一版我把断电做成"随时能操作"，结果模拟器跑出来断电反而**提高**了通关率
—— 因为玩家白拿进度又躲开了副教练。那不叫恐怖，那叫发福利。
改成"状态冻结"后，地狱 23.2% → 20.3%，史诗 4.8% → 2.9%，威胁才成立。）

## 评分系统

```
基础分    = 撑过的小时数 × 40
进度分    = min(题目进度, 达标线 × 1.5) × 8      ← 刷题机制
通关奖励  = 1500（只有【真通关】才有，不吃难度倍率）
耐久奖励  = 剩余门耐久 × 2（仅活到最后）
JC 惩罚   = 被 JC 次数 × 80
成就加分  = 本局解锁的成就分（C=80 / B=150 / A=300 / S=500）

总分 = (基础 + 进度 + 耐久 - JC惩罚 + 成就) × 难度倍率 + 通关奖励
```

注意「通关奖励」只给**真通关**（活到最后 + 进度达标）。
成就分是**本局达成即计分**（不管是不是首次解锁）——
早期版本写成"只有首次解锁才计分"，导致同样的表现第二局分数暴跌一千多，
而且和模拟器校准评级时的口径不一致。
「熬了个寂寞」拿不到这 1500 分，所以评级明显低一档。

难度倍率：简单 0.8 / 普通 1.0 / 困难 1.3 / 地狱 1.7 / 史诗 2.2

评级（带**难度上限**）：

| 评级 | 分数线 | 含义 | 难度上限 |
|---|---|---|---|
| D | < 700 | 保底 | — |
| C | ≥ 700 | 普通 | — |
| B | ≥ 1400 | 良好 · 非新手 | — |
| A | ≥ 3350 | 大佬 · 摸鱼高手 | 简单档最高 A |
| S | ≥ 4000 | 高手 · 十把可及 | 普通档最高 S |
| SS | ≥ 4700 | 神级 · 困难/地狱接近完美 | 困难、地狱最高 SS |
| SSS | ≥ 7700 | 传说 · 史诗接近完美 | **只有史诗够得到** |

**难度上限是硬性的**：简单档刷不出 S，普通档刷不出 SS，
**SSS 只有史诗档能拿到**。想要高评级只能往上打。

### 为什么这么定

**通关奖励占大头**（1500），所以"活着出去"远比"多撑几小时"重要 ——
不然赖着不死反而能刷分，不符合生存游戏的逻辑。

**通关奖励不吃难度倍率**，只让表现分吃。早期版本让通关奖励也吃倍率，
结果模拟器跑出来地狱/史诗通关清一色 SSS，评分完全失去区分度。

**评级线是用模拟器校准的**（`tools/score_sim.js`，三种玩法风格 × 5 档难度）：

```
新机制（JC 永远开门 + 同学打断 + 成就每局计分）下，每档 4000 局：

难度    真通关%  评级分布
简单     95.6%   B:51% A:48%
普通     90.9%   B:37% A:53% S:6%
困难     75.6%   B:19% A:20% S:42% SS:12%
地狱     19.8%   D:9% C:24% B:43% A:5% S:3% SS:17%
史诗      5.8%   D:15% C:22% B:42% A:10% S:5% SS:6% SSS:1%
```

门槛是取各难度**真通关局的分数分位**定的：

| 评级 | 对应分位 | 含义 |
|---|---|---|
| A | ≈ 简单档 p50 | 简单档打得好才够 |
| S | ≈ 普通档 p95 | 普通档 top 5%，"玩十把能摸到" |
| SS | ≈ 困难档 p90 | 困难/地狱接近完美 |
| SSS | ≈ 史诗档 p90 | 史诗 top 10%，非常难得 |

**SSS 只占史诗局的 1%** —— 这是故意的，它应该非常难得。

典型局面：

| 局面 | 分数 | 评级 |
|---|---|---|
| 被抓，撑 10 小时 | 560 | D |
| 熬了个寂寞（23h，进度 40%） | 1230 | B |
| 真通关，普通，一般发挥 | 3376 | S |
| 真通关，普通，完美（进度 105%） | 4260 | SSS |
| 真通关，地狱 | 5274 | SSS |
| 真通关，史诗，完美 | 8593 | SSS |

**未通关最高只能到 A**（要拿到 A 得撑很久且成就多）。
**简单难度上限是 S** —— 想要 SS/SSS 必须挑战更高难度。

## 积分排行榜

游戏内**本机前十**（`localStorage`，不需要服务器、不需要账号）。

每局结束后自动记录：分数、评级、难度、撑过的小时、题目进度、日期。
排序按分数降序，只保留前 10 条。

主界面底部可以查看，也可以单独清空（"清空排行榜"按钮，不影响成就）。

> 想要**跨设备/多人**排行榜就需要服务器了 —— 那是另一个量级的工程。
> 目前这个版本是纯静态页面，没有后端。

## 存档

用 `localStorage` 自动保存，不需要账号：

- 成就永久解锁（跨局累积）
- 每个难度的最高分
- 总局数 / 通关次数 / 无 JC 局数

主界面「最佳成绩」面板下方有**清除存档**按钮。
存档损坏会自动重置，不会崩。

## 关于平衡

难度**不是拍脑袋定的**。我写了个模拟器（`tools/sim.js`），
让一个"零延迟最优玩家"每档跑 5000 局，统计胜率：

| 难度 | 模拟胜率 | 主要死因 |
|---|---|---|
| 简单 | ~95% | — |
| 普通 | ~75% | 破门 |
| 困难 | ~50% | 破门 |
| 地狱 | ~20% | 主教练进门 |
| 史诗 | ~5% | 破门 |

（模拟玩家近乎完美，真人实际胜率会明显更低。）

### 一条重要的保命规则

**主教练堵在门口时，同学 JC 不会把门打开。**

这不是偷懒。第一版没有这条时，模拟器跑出地狱档 9.7% 胜率，
诊断后发现是这样的死法：

```
副教练危机逼你去刷题 7 秒 → 期间没法关门
      → 同学 JC 开门 + 主教练正好在门口 = 必死
```

玩家什么都做不了，这是**设计缺陷**，不是难度问题。加了这条之后胜率回到 41%。

### 最敏感的旋钮

`DIFF` 里的 **`backP`**（主教练从走廊退回办公室的概率）：

```
0.30 → 地狱胜率 1%
0.50 → 地狱胜率 41%
```

想调难度优先动它。改完可以跑 `node tools/sim.js` 验证。

## 部署到 GitHub Pages

**第一次用 GitHub？** 打开项目里的 `上传GitHub教程.html`（双击即可），
里面有每一步点哪儿的图文说明，从注册开始。

简要步骤：

1. 注册 github.com 账号，**一定要验证邮箱**（不验证开不了 Pages）
2. 右上角 `+` → `New repository`，仓库名填 `oi-night`，选 **Public**
3. `uploading an existing file` → 拖入 `index.html` / `style.css` / `script.js`
   （建议也传 `README.md` 和 `LICENSE`）
4. `Settings` → 左侧 `Pages` → Source 选 `Deploy from a branch`
   → Branch 选 `main`、文件夹选 `/ (root)` → `Save`
5. 等 1~2 分钟，访问 `https://<你的用户名>.github.io/oi-night/`

改了代码重新上传同名文件即可，等一会儿自动更新（记得 `Ctrl+F5` 强刷）。
